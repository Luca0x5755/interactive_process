# 12. 儲存模型 (Saving Model)

---

## 🎯 本章節任務與航行目標 (Mission & Objective)

**你好！我是「ML專案領航員」。**

經過一系列的數據探索、特徵工程、模型訓練與評估，你已經打造出一個性能優良的機器學習模型。現在，我們需要將這個辛苦得來的「智慧結晶」永久地保存下來。

*   **核心任務 (The "What")**: 將訓練好的模型物件，以及在預處理階段使用到的重要物件（如特徵縮放的 Scaler），序列化並儲存為檔案。
*   **最終目標 (The "Why")**: 實現「一次訓練，多次使用」。保存模型後，我們就可以在任何需要的時候，快速載入它來進行預測，而無需重新執行前面所有的訓練步驟，這是模型部署與應用的基礎。

## ⚙️ 步驟 0：啟航前的準備 (Pre-flight Check)

我們將使用 Python 內建的 `pickle` 函式庫，或 `joblib`（對於大型 numpy 陣列更高效）來進行物件的序列化。

> **領航員提示**：請確保你已執行完前面的流程，並準備好了最終訓練好的模型（例如，在 `11-0` 中得到的 `best_model`）以及在 `6-0` 中 `fit` 好的 `scaler` 物件。

---

## 🚀 步驟 1：理解要保存什麼

**【THINK】領航員引導式提問**
> 我們要保存的僅僅是那個最終的 `model` 物件嗎？
>
> **不完全是！** 一個完整的、可隨時部署的模型，包含兩個部分：
> 1.  **已訓練的模型 (The Brain)**: 這是我們訓練好的核心，例如 `RandomForestClassifier` 物件。
> 2.  **預處理元件 (The Glasses)**: 為了讓模型能「看懂」新的原始數據，我們必須使用**與訓練時完全相同**的預處理方式。這意味著，我們在 `6-0` 特徵縮放中 `fit` 好的那個 `StandardScaler` 物件，也必須一起保存下來！如果新數據的縮放方式與訓練數據不同，模型的預測將會是完全錯誤的。

---

## 🚀 步驟 2：執行保存

**【CODE】執行程式碼**
> 我們將使用 `joblib` 來保存模型和 `scaler`。`joblib` 在處理包含大型 NumPy 陣列的 scikit-learn 物件時，通常比 `pickle` 更高效。

```python
import joblib

# --- 1. 保存訓練好的模型 ---
# 假設你的最佳模型儲存在 best_model 變數中
if 'best_model' in locals():
    model_filename = 'final_model.joblib'
    joblib.dump(best_model, model_filename)
    print(f"✅ 模型已成功保存至 '{model_filename}'")
else:
    print("❌ 錯誤：找不到名為 'best_model' 的模型物件。請確認您已在 11-0 章節中訓練並選定最佳模型。")

# --- 2. 保存用於特徵縮放的 Scaler ---
# 假設你的 scaler 物件儲存在 scaler 變數中 (來自 6-0 章節)
if 'scaler' in locals():
    scaler_filename = 'scaler.joblib'
    joblib.dump(scaler, scaler_filename)
    print(f"✅ Scaler 物件已成功保存至 '{scaler_filename}'")
else:
    print("⚠️ 警告：找不到名為 'scaler' 的物件。在應用模型於新數據前，請確保您有正確的縮放器。")

```

**【ANALYSIS】領航員深度解析**
> *   **What (觀察)**：執行後，檢查你的專案資料夾，你會發現多了 `final_model.joblib` 和 `scaler.joblib` 這兩個檔案。它們是二進位檔案，無法直接用文字編輯器打開。
> *   **Why (思考)**：為什麼要分開保存？因為預處理和模型預測是兩個獨立的步驟。在真實的應用流程中，我們會先載入 `scaler` 對新數據進行轉換，然後再載入 `model` 進行預測。保持模組化是一個好習慣。
> *   **How (行動)**：除了 `scaler`，如果你在特徵工程中還使用了其他需要 `fit` 的轉換器（例如 `LabelEncoder`, `SimpleImputer`），也應該用同樣的方式將它們一一保存下來。
